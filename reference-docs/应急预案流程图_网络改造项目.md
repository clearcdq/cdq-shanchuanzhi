# PACS网络改造项目应急预案流程图

## 1. 应急预案总览

```
[事件发生] → [分级判断] → [应急响应] → [处置执行] → [恢复验证] → [事后复盘]
```

---

## 2. 事件分级与响应时间

| 等级 | 定义 | 触发条件 | 响应时间 | 处理期限 |
|------|------|----------|----------|----------|
| **P0 紧急** | 全院业务中断 | PACS完全不可访问，所有终端报错 | 5分钟内 | 30分钟恢复 |
| **P1 高** | 部分科室中断 | 1-2个院区无法访问PACS | 15分钟内 | 1小时恢复 |
| **P2 中** | 性能严重下降 | 调阅速度>30秒，丢包率>5% | 30分钟内 | 4小时改善 |
| **P3 低** | 单点故障 | 单个终端/单台交换机故障 | 1小时内 | 8小时修复 |

## 3. P0级应急预案流程（业务完全中断）

```
┌─────────────────────────────────────────────────────────┐
│  P0事件：PACS完全不可访问                                │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  步骤1：立即确认（5分钟内）                             │
│  ├─ 网络组：ping PACS服务器IP，测试连通性               │
│  ├─ 应用组：登录PACS系统界面，确认是网络还是应用问题    │
│  └─ 放射科：现场确认所有终端受影响情况                  │
│         ↓                                                 │
│  判断：是网络问题？ → 是 → 进入步骤2                    │
│           否 → 启动应用应急预案（另文）                  │
│                                                          │
│  步骤2：快速诊断（10分钟内）                            │
│  ├─ 检查核心交换机状态（电源、接口、CPU）               │
│  ├─ 检查院区间光纤链路（光功率、端口状态）              │
│  ├─ 检查PACS服务器网卡（链路、驱动）                    │
│  ├─ 查看交换机日志（是否有大量错误、告警）              │
│  └─ 判断故障点：                                        │
│        ├─ 核心交换机故障 → 立即切换到备用交换机        │
│        ├─ 光纤中断 → 启用备份链路（如有）或5G CPE      │
│        ├─ 服务器故障 → 切换到备用服务器                │
│        └─ 不明原因 → 执行步骤3                         │
│         ↓                                                 │
│  步骤3：执行回滚（如为新网络故障）                      │
│  ├─ 所有接入交换机端口切回至旧网络VLAN                │
│  ├─ 终端IP地址由DHCP改为旧网段（或重新配置）           │
│  ├─ PACS服务器IP暂时切回旧网络（如IP变更）             │
│  └─ 5分钟内完成，通知放射科验证业务恢复                │
│         ↓                                                 │
│  步骤4：业务恢复验证（15分钟内）                        │
│  ├─ 放射科医生打开CT影像，测试访问速度                 │
│  ├─ 多个科室测试，确保全范围覆盖                       │
│  ├─ 记录恢复时间，填写《事件报告》                      │
│  └─ 如未恢复，重复步骤2-3或升级至P0事件升级流程        │
│         ↓                                                 │
│  步骤5：事后复盘（24小时内）                            │
│  ├─ 召集项目组分析根本原因                             │
│  ├─ 编写《P0事件分析报告》                             │
│  ├─ 制定整改措施，更新应急预案                        │
│  └─ 向院领导汇报                                       │
└─────────────────────────────────────────────────────────┘
```

## 4. P1级应急预案流程（部分中断）

```
P1事件：单一院区PACS不可访问
  ↓
步骤1：定位故障院区（5分钟）
  ├─ 新院区无法访问 ←→ 老院区无法访问
  └─ 确定故障范围（某个VLAN/交换机）

  ↓
步骤2：诊断该院区网络（15分钟）
  ├─ 检查该院区核心交换机（电源、风扇、CPU）
  ├─ 检查接入交换机堆叠状态
  ├─ 测试该院区到PACS服务器的链路
  ├─ 测试该院区内部终端连通性
  └─ 检查防火墙策略（是否误阻断）

  ↓
步骤3：针对性处置
  ├─ 接入交换机故障：
  │    √ 因单台故障，未影响整体，待下班后更换
  │    √ 临时将受影响终端接入其他交换机端口
  ├─ VLAN配置错误：
  │    √ 快速修复配置（5分钟内）
  │    √ 验证后恢复
  ├─ 光纤衰减超标：
  │    √ 临时更换备用光纤
  │    √ 联系运营商检修
  └─ 其他：按P0流程处理

  ↓
步骤4：业务验证（30分钟内）
  ├─ 该院区所有放射科终端测试访问
  ├─ 记录性能数据（延迟、丢包）
  └─ 填写《P1事件处理单》

  ↓
步骤5：后续整改（7天内）
  ├─ 故障设备维修/更换
  ├─ 完善监控告警（如增加端口流量监控）
  └─ 更新应急预案
```

## 5. P2级应急预案流程（性能严重下降）

```
P2事件：网络拥塞，调阅速度慢
  ↓
步骤1：确认性能指标（10分钟）
  ├─ 部署iperf3测试：带宽是否达标
  ├─ 持续ping：延迟是否>20ms，丢包率>1%
  ├─ 查看交换机端口错误计数（CRC、collision）
  └─ 查看QoS策略是否正确应用

  ↓
步骤2：拥塞点定位
  ├─ 核心交换机上行链路利用率>80%？ → 检查和优化QoS
  ├─ 单台接入交换机负载过高？ → 临时限流或切换部分端口
  ├─ 某个终端产生异常流量（如病毒）？ → 隔离该终端
  └─ PACS服务器本身性能瓶颈？ → 信息科检查服务器

  ↓
步骤3：临时优化
  ├─ 调整QoS：临时提升PACS流量优先级
  ├─ 临时限流：限制非关键业务（如办公网）带宽
  ├─ 负载均衡：将部分终端切换到备用交换机
  └─ 告警用户：发布临时公告，告知正在优化

  ↓
步骤4：持续优化（2-4小时内）
  ├─ 分析流量峰值模式，调整QoS参数
  ├─ 如持续拥塞，考虑短期增加临时上行链路（5G CPE）
  └─ 记录优化效果，形成《性能调优报告》

  ↓
步骤5：根本解决（7天内）
  ├─ 评估是否需增加带宽或硬件扩容
  ├─ 优化PACS应用缓存策略
  └─ 必要时纳入二期改造
```

## 8. 事件报告模板

### 8.1 P0/P1事件报告（24小时内提交）
- 事件时间、持续时间
- 影响范围（科室、终端数、业务类型）
- 故障原因分析
- 处置过程记录（精确到分钟）
- 恢复时间与业务影响时长
- 根本原因与整改措施
- 责任人签字

### 8.2 事件复盘会议（48小时内）
- 参会人员：项目组全体+院领导（P0级）
- 议题：时间线复盘、决策评估、流程改进
- 输出：更新版的应急预案
